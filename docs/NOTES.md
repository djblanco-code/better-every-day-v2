# NOTES — things the next person needs to know

- 2026-10-21: `@supabase/supabase-js` 2.118 requires Node >= 22. CI and Vercel run Node 22; the dev machine still has Node 20.0.0 (works with EBADENGINE warnings). Upgrade local Node to 22 LTS when convenient: https://nodejs.org.
- 2026-10-21: Vercel env vars are per environment. Add NEXT_PUBLIC_* to Production AND Preview, or PR previews run unconfigured (the hello page says so instead of failing the build).
- 2026-10-21: a transient `npm ci` ECONNRESET in CI is a re-run, not a bug.
- 2026-10-21: NEXT_PUBLIC_* only reach the browser when referenced literally as `process.env.NAME`; reading them through a `process.env` object works on the server and is `undefined` on the client (the sign-in button threw a ZodError). `src/lib/env.ts` spells them out.
- 2026-10-21: the production URL is https://better-every-day-v2-neon.vercel.app (better-every-day-v2.vercel.app belongs to someone else). Update the GitHub OAuth app homepage and Supabase Site URL to the -neon one.
- 2026-10-21: Supabase redirect allow-list entries must match the WHOLE redirect URL including the query string. `https://*.vercel.app/auth/callback` did not match `.../auth/callback?next=%2Ftoday`, so Supabase fell back to the Site URL and the session never formed. The entry is now `https://*.vercel.app/auth/callback**`, and middleware forwards a stray `?code=` to the callback as a safety net.
- 2026-10-21: "Unable to exchange external code" from Supabase = the provider Client Secret does not match. Regenerate on the provider, paste again.
- 2026-10-21: RLS can be proven in the SQL editor without any secret: `begin; select set_config('request.jwt.claims', json_build_object('sub', <uuid>, 'role', 'authenticated')::text, true); set local role authenticated; select count(*) from <table>; rollback;` A stranger uuid returns 0, the owner uuid returns their rows. Migrations are applied by pasting `supabase/migrations/*.sql` into the SQL editor until the Supabase CLI is set up.
- 2026-10-21: the invite code is NOT an env var (PRD said INVITE_CODE; changed): it lives in `private.config` (schema hidden from the API, RLS on, anon/authenticated revoked) and is checked by `public.accept_invite(code)` (security definer). Clients cannot read the code or set `users.invited` (column-level update revoked). Rotate it with the insert in `supabase/migrations/0002_invite_gate.sql`. Current code is shared with friends out of band.
- 2026-10-21: CI (lint, typecheck, vitest, build, gitleaks) shipped in PR #1 as part of the PR process. `.gitleaks.toml` adds explicit rules for Anthropic (`sk-ant-`), Supabase secret (`sb_secret_`) and Google AI (`AIza`) keys on top of the defaults; the publishable `sb_publishable_` key is allow-listed on purpose.
- 2026-10-21: `npm run check` builds BEFORE typechecking on purpose: `next build` regenerates `.next/types` for the current branch; typechecking first after a branch switch fails on stale route types.
- 2026-10-21: seeding `public.banks` without the secret key: `node scripts/seed-banks.mjs --sql > seed.sql`, put the file on the clipboard (`clip.exe < seed.sql`), paste into the Supabase SQL editor, run. The Studio page blocks fetches to localhost (CSP), so a local file server does not work. With `SUPABASE_SECRET_KEY` in the env, `node scripts/seed-banks.mjs` upserts directly.
- 2026-10-21: v2 engine golden fixtures (`src/lib/recall/__fixtures__/golden.json`, 20 synthetic states) are generated by `please-hire-me/state/make_golden.py` from the v1 Python engine. Two Python-isms matter for byte equality: `round()` is banker-rounding (`pyRound`, `pyRound1`) and tier-4 ties sort by the `next_due` string.
- 2026-10-21: Today uses the BROWSER local date (sent to the server action, accepted only within a day of the server clock) so the plan rolls over at the user midnight, not UTC.
- 2026-10-21: the Supabase SQL editor "Potential issue detected" dialog appears when a `create table` and its `enable row level security` are in different statements; "Run and enable RLS" is safe (it only adds redundant enables).
- 2026-10-21: AI keys live in Supabase Vault via `set_ai_key` / `clear_ai_key` / `read_ai_key` (security definer). `read_ai_key` is granted to `authenticated` because the server gateway runs as the user; a user can therefore read their OWN key through the API, never anyone else's, and the app never renders it. If that is ever not enough, move the gateway to the service role and revoke the grant.
- 2026-10-21: `server-only` is aliased to an empty module in vitest.config.ts so gateway/loader modules can be unit-tested in Node.
- 2026-10-21: v1 import (`scripts/import-v1.mjs`) found 0 graded sessions and 0 reps in v1 (the key was never added there), so the only thing carried over is the program start date (2026-10-20), set in SQL. The script stays for anyone else migrating from v1.
- 2026-10-21: LeetCode statements live in `public.banks` track `statement` (not Storage as TASKS first said): one script, one table, same RLS, and a 10-minute server cache. `scripts/fetch-statements.mjs` takes only the ~330 slugs in the bank (318 matched; 9 are premium/unlisted and fall back to `premium_statements` or a link). Loaded per deployment; nothing from the dataset is committed.
- 2026-10-21: the v1 job import (`please-hire-me/scripts/export_jobs_sql.py <email> out.sql`, any account) collapsed 346 -> 329 applications and 405 -> 397 todos because v1 keyed rows by URL hash and a few URLs repeat (second req at the same company); v2 keeps the same ids so nothing else changes.
