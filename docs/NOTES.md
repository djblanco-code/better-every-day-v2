- 2026-10-22: mobile pass. Research on apps that work the same on Windows, Mac and iPhone (Linear, Notion, Todoist, Things-style PWAs) converged on five rules we now follow: (1) one bottom tab bar on phones with at most five tabs and 44px+ targets, a top bar on wide screens (`src/app/app-nav.tsx`); (2) `viewport-fit=cover` plus `env(safe-area-inset-bottom)` on the FIXED bar, not on body, so the iPhone home indicator never covers a tab; (3) tables turn into stacked cards under 768px (`table.tbl-cards` in `globals.css`: one class, no per-cell markup, so every future table gets it for free); (4) inputs are 16px on phones because iOS zooms the page on any smaller focused input; (5) the "Add to Home Screen" nudge waits for the second visit and never shows once the app runs standalone. Sources: web.dev "Add to Home Screen"/PWA checklist, MagicBell "PWA on iOS" guide, Smashing/Smart Interface Design Patterns on tap targets, the Progressier safe-area notes.
- 2026-10-22: Next 16 upgrade lessons. (1) A root layout that calls `cookies()` must NOT wrap it in a broad try/catch: Next signals "this route is dynamic" by throwing, and swallowing it makes every static page fail to prerender with an opaque Server Components error. Guard only the env check. (2) `eslint-config-next` 16 ships flat presets (`eslint-config-next/core-web-vitals`, `/typescript`), so FlatCompat goes away. (3) The React Compiler lint now errors on `useState(Date.now())` (use a lazy initializer), on `Math.random()` during render (move it into the click handler), and on a synchronous `setState` inside an effect (defer or derive). (4) `middleware.ts` is deprecated in favour of `proxy.ts` exporting `proxy`; same code. - 2026-10-22: migration 0008 wrapped `auth.uid()` in a subselect in all 59 policies (verified from `pg_policies`: 59 wrapped, 0 bare) and the index proof query found 0 tables with `user_id` but no leading index. - 2026-10-22: `sessionUser()` (`src/lib/supabase/session.ts`) replaced `getUser()` everywhere except account deletion. It uses `getClaims()`, which verifies the JWT signature locally because the project already signs with an ECC P-256 key (Settings > JWT Keys; the HS256 secret is "previous"). One network round trip removed per page, per action and per proxy run. Revocation now takes effect at token expiry (1 h) instead of instantly; acceptable for this app, and deletion still checks the Auth server.

- 2026-10-22: the pages used ten different width caps (max-w-xl to max-w-6xl), so Today looked narrow on a desktop while Jobs looked wide. Rule now, in `src/app/shell.tsx`: application screens (tables, boards, dashboards) are fluid up to 1600px (the Material 3 "extra-large" boundary) with side padding that grows with the window; reading and form pages keep a line-length cap. Sources: WFP design system (fluid for productive apps, max-width for text), Wix dashboard guidelines (fluid grid with a fixed cap, margins stretch), Material 3 window size classes (compact <600, medium <840, expanded <1200, large <1600, extra-large >=1600). Never stretch cards past the cap; add columns instead (Today and Home go two-column at 1024px).
- 2026-10-22: Phase 6 design notes. Today is "your day": check-in (sleep, energy, mood) → needs-you-today (dated Jobs and Network items) → the Recall plan sized to the time available → habits → glance. The engine's plan is never altered by the check-in; the client only marks slots past the time budget as "if time allows", so the golden tests and the plan history stay valid. Low energy (1-2) with no time chosen sizes the day to 40 min. Money is manual + journal only (no bank sync, PRD §8). The journal parser (v3) gets the user's habit names and the category list injected into the system prompt, so it can only map to things that exist; it never creates a habit or category.
