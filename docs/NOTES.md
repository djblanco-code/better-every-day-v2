# NOTES — things the next person needs to know

- 2026-10-21: `@supabase/supabase-js` 2.118 requires Node >= 22. CI and Vercel run Node 22; the dev machine still has Node 20.0.0 (works with EBADENGINE warnings). Upgrade local Node to 22 LTS when convenient: https://nodejs.org.
- 2026-10-21: Vercel env vars are per environment. Add NEXT_PUBLIC_* to Production AND Preview, or PR previews run unconfigured (the hello page says so instead of failing the build).
- 2026-10-21: a transient `npm ci` ECONNRESET in CI is a re-run, not a bug.
- 2026-10-21: NEXT_PUBLIC_* only reach the browser when referenced literally as `process.env.NAME`; reading them through a `process.env` object works on the server and is `undefined` on the client (the sign-in button threw a ZodError). `src/lib/env.ts` spells them out.
- 2026-10-21: the production URL is https://better-every-day-v2-neon.vercel.app (better-every-day-v2.vercel.app belongs to someone else). Update the GitHub OAuth app homepage and Supabase Site URL to the -neon one.
- 2026-10-21: Supabase redirect allow-list entries must match the WHOLE redirect URL including the query string. `https://*.vercel.app/auth/callback` did not match `.../auth/callback?next=%2Ftoday`, so Supabase fell back to the Site URL and the session never formed. The entry is now `https://*.vercel.app/auth/callback**`, and middleware forwards a stray `?code=` to the callback as a safety net.
- 2026-10-21: "Unable to exchange external code" from Supabase = the provider Client Secret does not match. Regenerate on the provider, paste again.
- 2026-10-21: RLS can be proven in the SQL editor without any secret: `begin; select set_config('request.jwt.claims', json_build_object('sub', <uuid>, 'role', 'authenticated')::text, true); set local role authenticated; select count(*) from <table>; rollback;` A stranger uuid returns 0, the owner uuid returns their rows. Migrations are applied by pasting `supabase/migrations/*.sql` into the SQL editor until the Supabase CLI is set up.
- 2026-10-21: CI (lint, typecheck, vitest, build, gitleaks) shipped in PR #1 as part of the PR process. `.gitleaks.toml` adds explicit rules for Anthropic (`sk-ant-`), Supabase secret (`sb_secret_`) and Google AI (`AIza`) keys on top of the defaults; the publishable `sb_publishable_` key is allow-listed on purpose.
